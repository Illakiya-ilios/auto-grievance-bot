# auto-grievance-bot
=======
# Civicline Grievance Desk

A React + FastAPI grievance assistant with an approval-first registration flow. Gemini classifies new chat requests and generates assistant replies using the grievance template and, for service-policy questions, administrator-uploaded reference documents. LangGraph manages grievance intake, tracking, escalation, and approval. PostgreSQL stores uploaded knowledge documents and submitted grievances.

## Request architecture

```text
React App.jsx → api.js → POST /api/chat → FastAPI main.py
                                        ├─ intent_detection.py → Gemini via llm.py (required)
                                        ├─ intent_router.py → response path
                                        ├─ every response → Gemini via llm.py
                                        ├─ document_question → Gemini embeddings → PostgreSQL/pgvector → Gemini via llm.py
                                        ├─ grievance → workflow.py (LangGraph)
                                        │    ├─ extract details → llm.py
                                        │    ├─ check required fields
                                        │    ├─ generate follow-up → llm.py
                                        │    └─ draft review → user approval
                                        └─ tracking/escalation → workflow.py + store.py
```

`main.py` is the HTTP controller and keeps per-conversation chat state. New intent routing uses Gemini, not local intent-classification rules; active tracking, escalation, and registration turns continue their current workflow. `intent_router.py` maps detected intents to processing paths. The grievance path enters the LangGraph workflow in `workflow.py`, which orchestrates LLM extraction and follow-up generation around required-field checks and the approval pause. All chatbot replies—including intake prompts, tracking and escalation updates, validation guidance, and submission receipts—are generated by Gemini using the grievance template and relevant conversation/backend context. `llm.py` contains Gemini calls; `store.py` handles PostgreSQL data access. The frontend receives the result as JSON and displays the assistant message or grievance review.

## Start the data services

Install and start PostgreSQL with the pgvector extension enabled. PostgreSQL is required to save grievances and uploaded knowledge documents; the application enables the `vector` extension during schema initialization, but the pgvector extension files must be installed for your PostgreSQL version.

## Run the API

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# Add GOOGLE_API_KEY to backend/.env; Gemini is required for chat.
uvicorn app.main:app --reload
```

Copy `backend/.env.example` to `backend/.env` and add your key as `GOOGLE_API_KEY=...`. Gemini is required for chat classification, extraction, follow-up questions, and responses. If Gemini is not configured or a request fails, the API returns an explicit error; it does not switch to local canned replies. Automatic API documentation endpoints are disabled. The API health check is at `http://localhost:8000/api/health`. Service-policy answers are grounded in uploaded reference documents; when those documents do not support an answer, Gemini explains that and can offer help preparing a grievance. The app does not directly transfer the chat to customer care.

The assistant checks required fields and contact format, and uses the generic grievance template as a checklist for one-at-a-time follow-up questions about applicable missing details such as date, location, impact, earlier complaint status, evidence, and requested resolution. It does not independently verify the truth of user-provided facts. After two failed contact-format checks, Gemini asks whether the user wants customer-care contact instructions. Set `CUSTOMER_CARE_CONTACT` in `backend/.env` to the official phone number, email address, or URL; Gemini can include it after the user agrees. The app does not directly transfer the chat to customer care.

The generic grievance intake fields are configured in `backend/app/templates/generic_grievance.json`; extraction, follow-up, and response-generation instructions are in `backend/app/prompts/`. Change those files to adjust the standard intake and replies without editing Python code. The responsible party is used as the grievance recipient. The current submission flow still requires a name and a phone number or email address, and chat attachments are not supported.

## Admin-managed knowledge documents

Set a strong `ADMIN_PASSWORD` in `backend/.env`, then open the separate dashboard at `http://localhost:5173/admin` and sign in. The dashboard only manages uploaded knowledge documents; it has no issue-template editor. Admin sessions expire after eight hours, on sign-out, or when the API process restarts.

Upload PDF or UTF-8 TXT reference documents. Text PDFs with up to 200 pages and 500,000 extracted characters are supported; scanned PDFs must be OCR-processed before upload. Individual uploads are limited to 10 MB. PostgreSQL stores the original uploaded file bytes alongside extracted text and overlapping chunks; Gemini creates 768-dimensional embeddings using `GEMINI_EMBEDDING_MODEL` (default `gemini-embedding-001`), and pgvector retrieves the five closest chunks by cosine distance for each document-backed chat request. User contact details are redacted before query embedding. Embeddings support retrieval only; they do not train or fine-tune the model. Existing documents are indexed automatically the next time a document-backed chat request is made. Before answering document questions or starting grievance intake, Gemini checks whether the topic is covered by the retrieved material. Out-of-topic questions and grievance reports are declined; only in-scope grievance reports proceed to intake. Policy answers must be supported by uploaded content, and the grievance template does not expand the document-supported topic. Uploaded documents can be removed from the dashboard.

## Approval and data handling

A chat turn can only produce a pending review. The LangGraph workflow pauses for a human decision, and the only PostgreSQL insertion path is the explicit `approve` decision endpoint; edit and cancel never insert a grievance. The PostgreSQL insert is idempotent per conversation. Names, phone numbers, and email addresses are redacted before Gemini calls.

This is a local development starter, not a production deployment. Conversation drafts currently live in API process memory, and the API has no user authentication or authorization. Before handling real personal data, add authenticated ownership checks, durable encrypted conversation storage, HTTPS, retention/deletion controls, rate limiting, and operational monitoring. Review the configured LLM provider's data terms before enabling it.
